## 内部接口草案

接口：`POST /internal/v1/mood-replies`，仅供受信任Java服务调用，不由浏览器直接访问。

请求头：`X-Internal-Token`与`X-Request-ID`。令牌从环境注入，Python缺少令牌则拒绝启动，比较凭据使用安全比较函数；Java侧缺少内部调用配置则在尝试生成时返回配置失败，不发送请求，不阻断不需要AI的心情保存。每次调用的ID由Java生成UUID，不沿用浏览器任意文本。首轮本地监听回环地址；正式部署的网络边界后续按部署环境核验。

请求体：`mood_type`、`content`。Java已经完成登录与资源归属校验；本接口不接受浏览器提供的user_id作为身份，不新增Python读取业务资料的权限。二者均为非空字符串：心情类型上限30个UTF-16代码单元，与现有列上限保守对齐；正文上限500个UTF-16代码单元，与现有表单一致。Java与Python显式采用同一计量方式，避免emoji在两端计数不一致。Java在保存/更新前校验；Python为内部契约再次校验。长度限制是本方案选择，并非原Java API已经具备的行为。

成功：HTTP 200，返回`request_id`、`reply_content`、`model_name`、实际提示词文本和可用调用元数据。正文必须有效且非空；缺失usage不虚构数值。提示词用于沿用现有ai_reply记录，不打印到运行日志。

响应示例（`prompt`是实际发送的system/user消息的确定性文本表示，非模型生成）：

```json
{
  "request_id": "Java生成的UUID",
  "reply_content": "有效的心情陪伴回复",
  "model_name": "当前配置的模型",
  "prompt": "system: ...\nuser: ...",
  "usage": {"prompt_tokens": null, "completion_tokens": null, "total_tokens": null}
}
```

Python继承当前心情提示词的用户可见目标，模型请求保留原有`thinking: disabled`与`max_tokens: 300`参数意图，实施时按配置供应商验证支持情况。Java校验HTTP成功响应的正文、模型名、prompt及关联ID；缺失或类型错误按响应不可用处理，不能仅凭HTTP 200返回成功。首轮不更改社区场景的提示词、调用方式或故障语义。

失败：内部认证失败401；输入错误422；模型不可用503、超时504、上游错误或响应不可用502。错误正文只提供稳定分类/安全描述和关联ID，不返回密钥、用户原文或上游原始响应。

Java转换为现有`AiReplyResult.failure`，保存status=0并显示既有兜底。无法得到实际prompt/model时允许记录空值，不把兜底文本或未知调用信息伪装成模型成功。默认不自动再次调用旧模型链，以免一次用户操作发生隐藏的第二次模型调用。

## 超时与失败边界

首轮建议先采用单次请求、不自动重试：Python模型整段调用限额18秒，Java内部调用读取等待22秒，心情创建/修改前端等待30秒；连接等待另设较短上限。这些是待实现并用延迟响应验证的初始参数，不是现有配置或性能保证。

lab的60秒超时不能直接复用到这条链。Python外层要覆盖完整调用的总时限，不只设置每次读取的等待时间。页面超时不等于供应商停止计算，也不自动证明取消计费；模型取消/客户端断开传播在后续有明确体验目标时单独验证。

Java继续负责心情和调用结果保存，不让Python与Java分别维护一份心情业务数据库。调用模型期间不新增持有数据库事务的设计。已存在的数据库写失败、并发编辑与重复提交边界需要结合测试保留证据，不能声称首轮一并解决。

## 验收与自测

1. 正常：选择需要AI回复，Java发送预期请求，Python返回有效回答，既有心情展示与ai_reply成功记录一致。
2. 关闭AI：不调用Python，不增加AI调用记录。
3. 模型超时/不可用/空回答：归类失败，Java保存失败状态、显示兜底；不能标成成功，也不自动重跑旧模型入口。
4. 内部接口令牌缺失/错误：模型调用前拒绝；凭据不在日志和响应中出现。
5. 原有登录、他人心情访问限制和社区回复路径回归通过。
6. 用预设模型HTTP跑通真实Java→Python本地HTTP，核对状态映射及各层超时；这只能证明集成契约，不证明真实回复质量。
7. Python目标及全量测试、Java相关及完整测试、前端测试与构建通过。需要真实模型和页面验收时再记录单独证据，不将离线通过写成已线上验证。

不执行初始化SQL，不自动提交、推送或部署。Docker与多服务部署在实际运行环境中再逐步落地。
