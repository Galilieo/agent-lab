# 工程化职责与心屿交接

本轮为职责带读与接入问题清单，不是心屿已经采用的接口设计或已实现的工程能力。Docker、具体服务接口和按需工程设施在心屿接入中设计实施，以正式路线第13/14节为准。

## 放回一次真实业务请求

建议在心屿接入时核验的主链：浏览器携带登录凭证→Java入口识别用户、校验业务访问、接纳/拒绝请求→通过受保护的内部接口调用Python→Python按已确认身份和范围取上下文、执行Agent/模型/工具→结果返回并按确定的数据归属保存。该链是职责方向，尚未核对心屿当前接口，不预先锁定存储、认证协议或部署拓扑。

| 事项 | 职责方向 | agent-lab当前能证明的部分 |
| --- | --- | --- |
| 身份与权限 | Java业务入口从可信登录态识别用户并校验资源访问；Python内部接口还须认证调用方、验证允许的资料/工具范围，不能仅靠请求里的user_id | 会话归属一致性校验已实现，但user_id可由调用方传入，未实现登录身份认证或知识库权限隔离 |
| 限流与预算 | 入口可按用户/请求频率限制；Python可限制昂贵模型并发及每轮模型/工具预算，具体数值按需求设计 | max_model_calls限制一轮逻辑调用；独立retry_model_call限制单次操作的尝试。两者都不是全局/按用户限流 |
| 日志关联 | 服务间传递并校验请求关联标识；把请求、逻辑调用、实际尝试和工具动作关联，按需记录元数据与结果分类 | 原生模型日志、调用表及独立重试失败日志已有局部验证；未完成跨Java/Python追踪和逐次尝试持久化 |
| 内容与工具安全 | 产品决定允许什么输入输出/动作，应用落实检查；资料是数据，身份和工具权限由程序强制，模型输出不能直接充当授权 | 参数校验、有限工具清单及部分Prompt数据边界已有实现；没有完整内容审核、认证或外部业务动作幂等机制 |

## 四个易混点

1. 归属校验不等于身份认证。main.py把request.user_id传给upsert_conversation，再恢复历史与保存当前问题；这能拒绝已存在会话的另一组ID，但如果身份本身可伪造，就不能凭“传入的ID相同”证明访问者是本人。心屿需从可信登录态建立身份与资源访问链。
2. 重试上限不等于限流。单个请求最多两次模型尝试，仍可能有很多用户同时进入；限制并发和请求频率解决的是其他维度。重试还会扩大上游尝试数，心屿需要把每轮预算、总耗时和服务容量放在一起判断。
3. 有日志不等于能关联整次请求。时间接近的两条日志可能来自不同用户；关联标识帮助把Java入口、Python编排和模型尝试串起来。只记录请求标识、分类、状态、耗时和必要用量，不因此打开完整问题/回答/密钥日志。
4. 模型判断不等于执行权限。即使模型说“允许查看某人的日记”，程序仍须按已认证用户的访问范围拒绝无权读取；把限制写进system_prompt不能代替服务层权限检查。模型生成的工具参数也要校验，执行有副作用的工具时另考虑幂等与确认。
