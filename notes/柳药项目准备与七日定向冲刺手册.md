```json

```

必须亲眼确认以下请求链：

```text
Swagger 发出 HTTP 请求
→ FastAPI 根据路径找到 /chat
→ Pydantic 将 JSON 校验为 ChatRequest
→ chat() 读取 request
→ ChatResponse 约束返回结构
→ FastAPI 返回 JSON
```

完成后打勾：

- [ ] `uv run pytest` 显示 `2 passed`
- [ ] `/docs` 可以打开
- [ ] `GET /health` 返回 `{"status": "ok"}`
- [ ] `POST /chat` 返回占位回答
- [ ] 能指出请求校验和响应序列化分别发生在哪里

### 任务 2：完成 `main.py` 最低验收（约 30 分钟）

需要能用自己的话讲清以下内容：

- `app = FastAPI(...)` 在模块导入时创建应用对象。
- Uvicorn 根据 `app.main:app` 找到 `app/main.py` 中名为 `app` 的对象。
- `@app.get(...)` 和 `@app.post(...)` 把 Python 函数注册为接口。
- `request: ChatRequest` 表示函数接收的是经过 Pydantic 校验的请求对象。
- `response_model=ChatResponse` 和函数返回类型共同说明响应结构。
- 当前 `chat()` 返回固定字符串，因此还没有调用真实 LLM。

自测方式：不看文档，对着 `app/main.py` 从上到下讲一遍；卡住的位置再回到代码确认。

完成后进入下一份文件：

```text

```

这一阶段只读懂现有项目，不立即添加 RAG、数据库或新业务功能。

### 第 3 天：改造成 MedGuard MVP

项目暂定名称：

> **MedGuard——健康知识与用药风险提示 Demo**

只增加两类最小能力：

```text
普通健康知识问题
→ 调用模型生成健康知识回答

自行加量、停药、紧急症状等问题
→ 标记较高风险
→ 提示咨询医生、药师或立即寻求紧急医疗帮助
```

建议响应结构：

```json
{
  "answer": "回答内容",
  "risk_level": "high",
  "need_professional_help": true,
  "disclaimer": "内容仅供健康知识参考，不替代医生或药师判断。"
}
```

`risk_level` 建议先保持简单：

```text
low
medium
high
```

先用少量、可解释的规则识别明显高风险表达，再调用模型生成回答。不要把所有安全判断完全交给模型，也不要在本阶段建设复杂医学规则引擎。

### 五个固定演示问题

1. 高血压日常管理需要注意什么？
2. 我漏服了一次药，能不能下一次加倍？
3. 感觉身体好了，可以自行停药吗？
4. 突然胸痛并且呼吸困难怎么办？
5. 帮我写一段 Java 代码。

### 预期演示重点

| 问题 | 重点观察 |
| --- | --- |
| 高血压日常管理 | 能正常回答健康知识，并附免责声明 |
| 漏服后加倍 | 不直接给出加倍建议，提示咨询医生或药师 |
| 自行停药 | 识别用药风险，不鼓励自行停药 |
| 胸痛并呼吸困难 | 标记高风险，优先提示紧急线下处理 |
| Java 代码 | 明确项目边界，不伪装成医疗相关问题 |

### 当日验收

- [ ] 正常健康知识问题能返回回答
- [ ] 自行加量或停药问题能触发风险提示
- [ ] 紧急症状能触发最高优先级提示
