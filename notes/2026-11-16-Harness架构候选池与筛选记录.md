### 2.1 维护与发布需要分开看

本轮另外核实到以下非 prerelease 发布记录：pi v1.5.2（11-10）、Hermes v0.23.1（11-10）、Goose v1.59.1（11-14）、Pydantic AI v2.68.0（11-12）、AgentScope v2.0.11（10-27）、OpenHands SDK v1.62.0（11-11）。这是查询时的发布元数据，不代表本机版本，也不证明本页所读 HEAD 的代码已包含在该发行版。

发现的筛选问题：

- AutoGen 的仓库 archived 字段为 false，但当前 README 明确声明不再维护并推荐 Microsoft Agent Framework。两项证据分别保留；新底座优先比较后继，旧设计只作历史材料。
- Goose 旧 block/goose 地址已迁移到 aaif-goose/goose；OpenHands 的运行核心应跟进 software-agent-sdk，不能只读产品前端仓库。
- Aider、Alibaba DeepResearch 有历史价值，但本轮最近 push 较早；不能因知名或旧榜高分直接选作新项目当前底座。
- Youtu-Agent 元数据许可证为 NOASSERTION，但实际 LICENSE 写明 MIT，需读原文而非只读标签；其依赖、模型与数据许可仍分别核对。
- PAST-Bench 是专项研究基准，仓库规模较小；可以参考实验设计，不作为“成熟生产框架”推荐。Hermes+ 是其研究实现，不能与当前 Hermes 上游混用。
- 代码里的 evaluator 可能是产品内的“判断是否通知 / 是否完成”，不必然是外部质量评测系统。nanobot 的通知 evaluator 就属于前者。

## 3. 横向比较的架构问题

| 设计问题 | 本轮读到的不同实现 | 对专用研究 Agent 要验证什么 |
| --- | --- | --- |
| 核心循环与产品层怎样分工 | pi 分 Agent 核心与 AgentSession；Hermes 当前循环委托多段 turn helper；mini-swe-agent 把循环、模型和环境保持紧凑 | 新增一种研究工具 / 停止条件时要改哪里；异常能否统一记录；避免把工作台逻辑放进工具循环 |
| 执行步骤怎样表示 | Goose 将操作组织成可重入状态机 / effects；LangGraph 采用显式状态与条件路由；Pydantic AI 通过 Capability hooks 包装运行阶段 | 人工确认、失败续跑、取消和全局预算在并发 / 恢复时是否仍成立；不按概念数量评价 |
| 完整历史与模型输入怎样分开 | pi 从会话生成输入投影；OpenHands 保留追加事件并形成压缩 View；Hermes 使用压缩与历史检索恢复 | 原文 / 工具记录能否保留，裁剪后能否重读；不能用摘要覆盖唯一证据 |
| 超长上下文怎样处理 | pi 保留近期窗口并写入压缩条目；OpenCode 有前台 / 后台摘要与溢出触发；Hermes 比较摘要、恢复检索及不同压缩策略 | 多次压缩后否定、版本、硬要求是否丢失；压缩本身的耗时 / Token 是否计入总成本 |
| Memory 与 Skills 怎样协作 | Hermes 有 provider 生命周期和后台复盘；nanobot 有文件记忆；AgentScope 有文件化 / ReMe / Mem0 中间件；Learn-Claude-Code 分章演示 | 什么是事实、什么是经验候选；更新 / 删除 / 隔离是否有效；不能因为保存了 Skill 就声称持续变强 |
| 预算是不是硬限额 | mini 在下一次 query 前检查累计 cost，单次完成后仍可能超过金额阈值；AgentScope ReplyBudget 使用累计用量提示并限制下一步工具 | 提示模型收尾与原子预留上限分开；按任务而非每轮重置；失败、后台复盘和子 Agent 也计费 |
| 工具如何执行 | 函数调用、MCP 和 smolagents 的代码行动具有不同表示与执行代价 | 同任务检查成功率、错误参数、工具次数；采用 CodeAct 另需运行隔离，当前只读研究范围不默认扩张 |
| 评测怎样与执行解耦 | Youtu 拆 preprocess / rollout / judge / stat；Pydantic Evals 从 spans 检查工具；pi 将对照组、重复、隔离与报告交给外层 runner | 同一运行轨迹可以重判分；不重新调用模型来修补旧分数；记录缺失而不是填零 |

这些是静态阅读得到的设计差异，不是实测优劣。尤其不能把“框架声称可恢复”当作我们的模型请求、资料快照与操作去重已经可靠。

“有 benchmark”仍有不同证据强度：pi 当前已读运行器会输出协议、计划任务、逐题结果、成对报告，但输出默认忽略入 Git，本轮没有确认公开提交的完整结果；Hermes 压缩评测保存局部结果，真实 transcript 未公开。报告中必须保留这些复现限制。

## 7. 怎样从候选池走向可采用方案

下一阶段比较应使用同一批本项目任务，而不是把不同排行榜拼成分数表：

- 固定模型、工具、资料、预算与评分版本，分别比较执行循环、压缩、记忆或并行中的一个变化。
- 冻结资料回放与在线搜索分开；模型 / 搜索变化不能归功于 Harness。
- 先验证错参、取消、重复恢复、未知请求结果和用量缺失，再评价正常任务成功率。
- 运行成本包含摘要、后台记忆整理、重排及裁判，并分别显示用户任务成本和评测额外成本。
- 对照模式按任务族配对；记录重复次数、全部失败和未完成样本。保留题不能调参后继续当未见题。
- 标明最终实际采用哪些库 / 版本、借鉴哪些设计，以及哪些效果尚无证据；不声称“复刻某大项目所以生产级”。

本轮只完成更广的候选核查与部分架构源码阅读，没有安装或运行这些项目，没有下载模型 / 数据集、调用付费模型、提交、推送或部署。候选池保持开放；本页不宣布最终框架或最优 Harness。
