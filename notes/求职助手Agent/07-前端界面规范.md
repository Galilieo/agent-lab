# 07 前端界面规范

日期：2026-11-16。状态：已与用户确认。前端不是本项目重点，目标是**实现简单、看着舒服、用着顺手**。页面长什么样，直接看[静态原型](./prototype/index.html)（第 8 节）。所有样式通过 Ant Design 的主题配置（`ConfigProvider` 的 `theme`）统一管理，页面里不写零散的颜色值。

## 1. 已确认的选择

| 项目 | 选择 | 理由 |
| --- | --- | --- |
| 配色 | **莫兰迪雾蓝**：暖灰底加灰调的蓝 | 柔和、安静，长时间审阅不累；避开当前 AI 产品常见的深青、紫色和高饱和蓝 |
| 导航 | 左侧导航，可折叠 | V2 加面试、记忆等页面时位置够用 |
| 暗色模式 | V1 只做亮色 | 颜色都放在主题配置里，以后切换 Ant Design 的暗色算法再检查自定义颜色即可 |
| 窄屏 | 能用就行 | 窄屏时导航收起，原文和改写改为上下排列；不专门设计手机版 |

## 2. 配色

| 用途 | 颜色 | Ant Design 主题项 |
| --- | --- | --- |
| 主色（按钮、链接、选中） | `#50687F` | `colorPrimary`、`colorLink`、`colorInfo` |
| 页面底色 | `#F4F2EE` | `colorBgLayout` |
| 侧栏底色 | `#ECE9E3` | `Layout.siderBg`，`Menu.itemBg` 设为透明 |
| 导航选中底色 / 文字 | `#DCE3EA` / `#3B5268` | `Menu.itemSelectedBg` / `Menu.itemSelectedColor` |
| 卡片、输入框底色 | `#FFFFFF` | `colorBgContainer` |
| 正文 | `#2E2E2C` | `colorText` |
| 次要文字 | `#6B6A66` | `colorTextSecondary` |
| 辅助信息（时间、计数） | `#8A8984` | `colorTextTertiary`；对比度较低，只用于非关键信息 |
| 边框 / 分隔线 | `#E2DFD8` / `#EAE7E1` | `colorBorder` / `colorBorderSecondary` |
| 成功 | `#5B8A4A` | `colorSuccess` |
| 警告 | `#B9842F` | `colorWarning` |
| 错误 | `#B5534A` | `colorError` |

状态颜色统一偏灰调，与主色协调；同时保证三种状态之间能一眼区分。实现后在页面上实际看一遍，对比度不够再微调，改动只发生在主题配置里。

## 3. 字体与疏密

- 字体：系统字体栈，`-apple-system, "PingFang SC", "Hiragino Sans GB", "Microsoft YaHei", sans-serif`，不引入网络字体。
- 界面文字 14px（Ant Design 默认）；**简历正文和改写内容 15px、行高 1.7**，因为这是主要阅读内容。
- 正文区最大宽度约 1200px，居中；原文、改写两栏各自不超过约 40 个汉字一行。
- 圆角 `borderRadius: 6`；阴影只在弹出层使用，卡片用细边框区分。
- 数字（要求覆盖条数、改写计数）使用等宽数字 `font-variant-numeric: tabular-nums`，变化时不跳动。

## 4. 布局

```text
┌──────────┬────────────────────────────────────┐
│ JobPilot │ 页面标题 + 主要操作                  │
│          ├────────────────────────────────────┤
│ 事实库    │                                    │
│ 岗位      │ 内容区（白色卡片，放在暖灰底上）       │
│ 改写记录  │                                    │
│ 面试 V2   │                                    │
│ ─────    │                                    │
│ 账号      │                                    │
└──────────┴────────────────────────────────────┘
```

- 侧栏宽 200px；窗口宽度小于 992px（Ant Design 的 `lg` 断点）时自动收起。
- 每页一个主要操作按钮（`type="primary"`），其他按钮用默认样式，避免满屏强调色。

## 5. 改写审阅页（核心页面）

- 每条改写一行，左边原文、右边改写；窄屏改为上下排列。
- 每条下方显示：检查结果标签、依据的事实编号（点击展开事实原文）、接受 / 不用按钮。
- 检查结果的标签：

| 状态 | 样式 |
| --- | --- |
| 检查通过 | 成功色标签 |
| 修订后通过 | 警告色标签，注明修订次数 |
| 已回退原文 | 灰色标签，后面用错误色文字写明原因，例如「改写写了“主导”，事实里没有」 |
| 待审阅 | 无标签，接受 / 不用按钮可见 |

- 页面顶部显示汇总：几条改写、已接受几条、待审阅几条；提供「接受全部通过项」。

## 5.1 完整简历预览与编辑（2026-11-16 加入）

参照 ASu-skills 的可编辑 HTML 简历，功能清单见 [01 F5](./01-功能设计.md#f5-完整简历预览编辑与导出v1)。

- 简历本身用**简历模板的样式**（白纸、A4、黑色正文），不用应用的莫兰迪配色；只有外层工具栏和页面用应用样式。
- 实现方式：后端把 `tailored_resume` 渲染成完整的 HTML（模板加内嵌编辑脚本），前端用 `iframe` 显示。编辑脚本自带工具栏；在应用里运行时，通过 `postMessage` 把修改交给外层页面保存到服务器；作为导出文件单独打开时，改为保存在浏览器本地。这样编辑器只写一份。
- 自动一页：测量内容高度与 A4 可用高度的比例，超出时每次把字号减 0.5px、行距减 0.05，最多若干步；状态文字显示「一页内 · 占用 94%」或「超出 1 页」。
- 打印样式：`@page { size: A4; margin: 12mm; }`，打印时隐藏工具栏和分页线。
- 手动修改过的改写条目，左侧显示一条细竖线，悬停显示依据检查的提示。

## 6. 用起来顺手的细节

这些比配色更影响体验，每个页面完成时对照检查：

1. **等待有进度。** 改写这类后台任务显示当前步骤（规划 → 改写 → 检查 → 修订）和已用时间，不只是转圈；离开页面再回来能继续看到进度。
2. **决定可以改。** 接受 / 不用随时可以改回来，导出前都能调整。删除按 [02 第 5.3 节](./02-技术架构与数据模型.md#53-数据删除)做二次确认。
3. **空页面给出下一步。** 例如事实库为空时显示「上传一份简历，自动拆成经历事实」和上传按钮，不只写「暂无数据」。
4. **出错说人话。** 说明发生了什么、可以怎么做，并提供重试；不显示原始异常。表单出错时保留已填写的内容。
5. **列表加载用骨架屏**，避免页面闪动和跳动。
6. **文案简短直接。** 按钮以动词开头（「开始改写」「导出 DOCX」），不用「确定」「提交」这类含糊的词；成功提示不加感叹号。

## 7. 实现方式

- 主题配置集中在 `web/src/theme.ts`，在 `main.tsx` 用 `ConfigProvider` 包住应用；同时用 Ant Design 的 `App` 组件提供 message、modal 的上下文。
- 页面里需要颜色时，通过 `theme.useToken()` 读取，不写死色值。
- 不引入额外的 CSS 框架（Tailwind 等）和图标库，图标用 `@ant-design/icons`。

## 8. 静态原型

[`prototype/index.html`](./prototype/index.html) 是 V1 全部页面的静态原型，用浏览器直接打开即可（VS Code 的 Live Server 也可以）。它只用于参照布局、文案和交互，**不是要复用的代码**：实现时用 Ant Design 组件重写，颜色从主题配置读取。原型里的数据都是虚构的。

- 右下角「显示实现标注」会在每个区域下方显示实现要点：用哪个组件、调用哪个接口、对应哪条设计。
- 改写审阅页的「接受 / 不用」「接受全部通过项」可以点击；改写记录页可以切换查看空状态；账号页可以走一遍删除账号的弹窗。
- 窗口宽度小于 992px 时，导航收起为顶部菜单，原文和改写改为上下排列。

| 页面 | 原型位置 | 主要组件 | 主要接口 |
