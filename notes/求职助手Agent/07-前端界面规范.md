# 07 前端界面规范

日期：2026-11-16。状态：已与用户确认（同日修订为对话式，见下方修订记录）。前端不是本项目重点，目标是**实现简单、看着舒服、用着顺手**。页面长什么样，直接看[静态原型](./prototype/index.html)（第 8 节）。所有样式通过 Ant Design 的主题配置（`ConfigProvider` 的 `theme`）统一管理，页面里不写零散的颜色值。

> **2026-11-16 修订：** 原版是「页面 + 表单」的多页面后台布局。用户看过原型后认为交互方式与设想不符，改为**对话为主的 Agent 界面**：左侧对话、右侧产物面板，对话与岗位软绑定，另有岗位库和「我的」两个页面。视觉风格从「莫兰迪雾蓝（暖灰底）」改为「极简雾蓝」：极简中性的骨架加雾蓝主色。选型过程比较过四种布局（对话加右侧产物、简历为中心、纯对话加卡片、岗位工作台）和五种视觉风格，结论如下。

## 1. 已确认的选择

| 项目 | 选择 | 理由 |
| --- | --- | --- |
| 布局 | **对话 + 右侧产物面板**（参考 Open Canvas、Claude 的做法） | 一边聊一边看简历变化，「说一句 → 看效果 → 再说」最顺；Agent 感强。另外三种布局：简历为中心的 Agent 感弱；纯对话的结果容易被聊天记录冲走；岗位工作台更像业务系统 |
| 对话与岗位 | **软绑定**：每段对话最多一个「当前岗位」，可切换、可解除 | 保留「一个岗位一个岗位地准备」的思路，又不限制 Agent 读取其他岗位做对比。规则见第 5 节 |
| 视觉风格 | **极简雾蓝**：白底、浅灰侧栏、大圆角、灰色无边框的用户气泡；主按钮、选中状态、链接用雾蓝 | 像当前的通用 Agent 一样干净，又有自己的颜色，不像套壳；雾蓝不刺眼，长时间看简历不累 |
| 页面 | 工作台（首页，P1）、对话、岗位库与岗位详情、我的（经历 / 简历 / 记忆）；账号放在左下角头像菜单 | 侧栏保持简洁，内容类入口合并到「我的」 |
| 跟通用 Agent 的区别 | 打开先看到求职数据（工作台）；产物面板为主角；**依据追溯**；对话里用领域卡片与领域快捷操作 | 只做成聊天框会被当成套壳；区别要一眼可见（00 第 1.5 节） |
| 组件库 | Ant Design + **Ant Design X**（`@ant-design/x`） | Ant Design X 与 Ant Design 同一体系，有现成的对话组件，对话界面基本不用手写 |
| 暗色模式 | V1 只做亮色 | 颜色都放在主题配置里，以后切换暗色算法再检查自定义颜色 |
| 窄屏 | 能用就行 | 侧栏变抽屉；右侧面板变成全屏层，由顶部「查看结果」按钮打开 |

## 2. 配色（极简雾蓝）

| 用途 | 颜色 | Ant Design 主题项 |
| --- | --- | --- |
| 主色（主按钮、链接、选中） | `#50687F`，悬停 `#3F566C` | `colorPrimary`、`colorLink`、`colorInfo` |
| 主色浅底（选中的对话、岗位标签） | `#E4EAF0`，其上文字 `#3B5268` | `Menu.itemSelectedBg` / `Menu.itemSelectedColor` 等 |
| 页面底色、对话区 | `#FFFFFF` | `colorBgLayout`、`colorBgContainer` |
| 侧栏底色 | `#F6F6F4` | `Layout.siderBg` |
| 右侧面板底色 | `#FAFAF8` | 面板容器样式 |
| 用户消息气泡 | `#F2F2F0`，无边框 | Bubble 的样式 |
| 正文 / 次要文字 / 辅助信息 | `#1F1F1F` / `#5F5F5B` / `#8F8F8A` | `colorText` / `colorTextSecondary` / `colorTextTertiary` |
| 边框 / 分隔线 | `#E6E6E2` / `#EFEFEC` | `colorBorder` / `colorBorderSecondary` |
| 成功 / 警告 / 错误 | `#5B8A4A` / `#B9842F` / `#B5534A` | `colorSuccess` / `colorWarning` / `colorError` |

颜色只用在主要操作和状态上；大面积是白色和浅灰。状态颜色偏灰调，与主色协调。实现后在页面上实际看一遍，对比度不够再微调，改动只发生在主题配置里。

## 3. 字体与疏密

- 字体：系统字体栈，`-apple-system, "PingFang SC", "Hiragino Sans GB", "Microsoft YaHei", sans-serif`，不引入网络字体。
- 界面文字 14px；对话正文行高 1.75；简历内容按简历模板的样式（第 5.2 节）。
- 对话区内容最大宽度约 860px，居中，宽屏下读起来不累。
- 圆角 `borderRadius: 10`；输入框 16px 圆角，带很淡的阴影；其他阴影只在弹出层使用。
- 数字（覆盖条数、计数）使用等宽数字 `font-variant-numeric: tabular-nums`。

## 4. 布局

```text
┌────────────┬──────────────────────────┬──────────────────────────┐
│ JobPilot   │ 标题 · [当前岗位 ▾]        │ 简历 | 匹配报告 | 岗位 | … │
│ ＋ 新对话   ├──────────────────────────┼──────────────────────────┤
│ 岗位库      │                          │                          │
│ 我的        │  对话（消息、工具步骤、    │  右侧产物面板             │
│ 最近对话    │  确认卡片）               │  （可编辑的简历、报告等）   │
│  💼 岗位对话 │                          │                          │
│  💬 普通对话 │ [输入框：文字、附件、截图] │                          │
│ (头像菜单)  │                          │                          │
└────────────┴──────────────────────────┴──────────────────────────┘
```

- 侧栏约 230px：新对话、岗位库、我的、最近对话（岗位对话和普通对话用不同图标）、底部头像菜单（账号设置、退出登录）。
- **产物面板为主角**：对话列约四成、右侧面板约六成；面板可以关闭、可以放大成全屏（编辑简历时）。
- 没有内容的对话（普通提问、新对话）不显示面板。
- 每个视图最多一个主要按钮（`type="primary"`）。

## 5. 对话页

### 5.1 消息与确认

- **工具步骤**：Agent 调用的工具显示为一行可折叠的进度（「✓ 已完成 4 步 · 用时 21 秒」），展开看每一步做了什么、读了什么。
- **确认卡片**：所有写入操作（新增或修改事实、修改简历条目、写记忆、删除）都以卡片出现，用户点确认才执行；需要用户做选择的问题（例如职责程度）也用卡片。确认后卡片变成一行结果文字。
- **系统提示**：关联、切换或解除岗位时，在对话中显示一行居中的灰色提示。
- **输入框**：支持拖入 PDF、DOCX、TXT、Markdown、HTML、图片；Enter 发送，Shift + Enter 换行；回复流式显示，生成中可以停止。
- **新对话**：欢迎语加四个入口建议（上传简历、发 JD 或截图、从岗位库选一个、补充经历）。
- **领域卡片**：匹配结果用「要求 · 判断 · 依据编号」的小表格；新增事实用前后对比卡片（＋ 内容、来源、职责程度、版本变化）；不用大段文字。
- **领域快捷操作**：回复下方根据状态给出按钮，例如「查看每条的依据」「为什么有一条被回退」「对比另一个岗位」，点了填进输入框或切换面板。
- **提问卡片**（不确定就问，01 F1）：原文对不上、说法矛盾、职责程度不明、缺少关键信息时出现；一轮最多一张，多个问题合并，每个问题给出选项与「先跳过」。
- **撤销**（P1）：已执行的写入在结果行旁边提供「撤销」。

### 5.2 右侧面板

面板标签随对话状态变化：

| 对话状态 | 面板标签 |
| --- | --- |
| 有当前岗位、已生成简历 | 简历 · 匹配报告 · 岗位 · 用到的事实 |
| 有当前岗位、已匹配未生成 | 简历（空状态，带「生成定制简历」按钮）· 匹配报告 · 岗位 |
| 有当前岗位、未匹配 | 岗位 |
| 没有当前岗位，但改动了事实库 | 事实库变化 |
| 普通对话、新对话 | 不显示面板 |

**简历标签**参照 ASu-skills 的可编辑 HTML 简历，功能清单见 [01 F5](./01-功能设计.md#f5-完整简历预览编辑与导出v1)：

- 简历本身用**简历模板的样式**（白纸、A4、黑色正文、雾蓝标题线），不用应用配色；只有外层工具栏用应用样式。
- 后端把 `tailored_resume` 渲染成完整的 HTML（模板加内嵌编辑脚本），前端用 `iframe` 显示。编辑脚本自带工具栏；在应用里运行时，通过 `postMessage` 把修改交给外层保存到服务器；作为导出文件单独打开时，保存在浏览器本地。编辑器只写一份。
- 面板里按比例缩小显示，放大按钮切换为全屏编辑。
- 自动一页：测量内容高度与 A4 可用高度的比例，超出时每次把字号减 0.5px、行距减 0.05，最多若干步；状态显示「一页内 · 占用 94%」或「超出 1 页」。
- 打印样式：`@page { size: A4; margin: 12mm; }`，打印时只输出简历。
- 条目悬停显示依据检查结果（通过 / 修订后通过 / 已回退及原因）；修订或手动修改过的条目左侧有一条细竖线。
- **可追溯改写的保证说明**：简历顶部固定一行「改写 N 条 · 每条都能追溯到你确认过的事实 · M 条因依据不足保留原文」。
- **依据追溯**：点「显示依据」，每条改写后出现事实编号；点编号显示事实原文、来源（简历原文片段或对话补充）和职责程度；回退的条目标「改写依据不足已回退」。依据标签不进入导出和打印。
- **版本过期提示**：简历基于的事实库版本落后于当前版本时，顶部显示「这份简历基于事实库 v4 生成，事实库已更新到 v5」，提供「重新生成」（旧版本保留）和「先不用」。

**匹配报告标签**：顶部一行汇总标签（硬性要求覆盖、表达缺口、部分覆盖、未覆盖），下方表格：要求、判断（四种颜色）、依据与建议。不显示百分比匹配分（01 F3）。

### 5.3 当前岗位（软绑定）

- 对话里第一次解析出 JD 时，把它设为这段对话的当前岗位，并存入岗位库，同时显示系统提示。
- 当前岗位**只决定**右侧面板显示哪个岗位、工具默认用哪个岗位；**不限制** Agent 读取其他岗位做对比。
- 标题旁的岗位标签可以点开菜单：查看当前岗位、切换到岗位库里的其他岗位、解除关联。没有当前岗位时，标签显示「未关联岗位」，也可以点开去选。
- 同一段对话里再发一个 JD：新岗位照样存入岗位库，Agent 先回答（例如对比两个岗位），再用确认卡片问「新开对话 / 切换到新岗位 / 保持不变」。

## 6. 工作台、岗位库与「我的」

**工作台**（首页，P1；P1 未完成前用岗位库代替首页）：问候语、输入框（发出后新建对话）与入口建议；三张状态卡片：经历事实库（条数、版本、待确认）、不编造记录（改写条数、可追溯条数、回退条数）、记住的偏好；岗位进度看板（未匹配 / 已匹配 / 已生成简历 / 已投递），点卡片回到岗位对话。

**岗位库**：卡片列表，显示岗位名、薪资、公司、地点、到岗天数和匹配摘要；按方向、技术关键词、城市、薪资（P1）、进度筛选，标签旁显示数量（P1）。点击进入岗位详情。顶部「我的岗位 / 公共岗位」切换，公共岗位是 V2。

**岗位详情**：基本信息网格（公司、地点、薪资、每周到岗、实习时长、学历、毕业时间、截止日期、投递渠道、岗位链接），每格可点击修改或留空，标「AI 提取」或「你填写」，没写的显示「未填写」；「＋ 添加字段」（P1）；下面是职责、硬性要求、加分项、关键词和 JD 原文。按钮：回到这个岗位的对话（或用这个岗位开始对话）、删除。**投递记录**（P1）：标记已投递后显示时间、渠道、当时的简历（查看、下载 PDF）、进度选择和「与现在对比」（简历条目差异、投递后事实库的变化、风险提醒）。

**我的**：顶部三张概览卡（经历事实条数与版本、定制简历份数、记忆条数），下面三个标签：

- **经历**：按经历分组的事实列表，可确认、修改职责程度、编辑、删除，可上传或粘贴简历、补充事实、提交新版本；对话中补充的事实标「对话中补充」。
- **简历**：每份定制简历一行，显示岗位、基于的事实库版本、状态、更新时间；「打开」回到对应对话。
- **记忆**：求职偏好与写作偏好列表，可修改、删除；说明「记忆只保存偏好，不保存经历」。

**账号设置**（头像菜单进入）：登录信息、退出登录、删除账号（两阶段，见 02 第 5.3 节）。

## 7. 用起来顺手的细节

这些比配色更影响体验，每个页面完成时对照检查：

1. **等待有进度。** 工具步骤实时更新；改写这类长任务显示当前步骤和已用时间；离开页面再回来能看到结果或继续的进度。
2. **改动先确认，确认后可调整。** 写入都有确认卡片；简历条目确认后仍可在面板里改；删除做二次确认。
3. **空状态给出下一步。** 新对话有入口建议；没有简历时提示「上传一份简历」；面板空状态带按钮。
4. **出错说人话。** 说明发生了什么、可以怎么做，并提供重试；不显示原始异常。输入框出错时保留已输入的内容。
5. **列表加载用骨架屏**，避免闪动和跳动。
6. **文案简短直接。** 按钮以动词开头（「确认加入」「生成定制简历」「导出 PDF」），不用「确定」「提交」这类含糊的词；成功提示不加感叹号。

## 8. 实现方式与静态原型

- 主题配置集中在 `web/src/theme.ts`，在 `main.tsx` 用 `ConfigProvider` 包住应用；同时用 Ant Design 的 `App` 组件提供 message、modal 的上下文。页面里需要颜色时通过 `theme.useToken()` 读取。
- 对话部分用 Ant Design X：会话列表、消息、输入框、附件、工具步骤、欢迎页建议都有对应组件；流式数据用浏览器原生能力读取 SSE（02 第 6 节），不另加状态库。
- 不引入额外的 CSS 框架（Tailwind 等）；图标用 `@ant-design/icons`。

[`prototype/index.html`](./prototype/index.html) 是 V1 的静态原型，用浏览器直接打开即可。它只用于参照布局、文案和交互，**不是要复用的代码**：实现时用 Ant Design / Ant Design X 组件重写，颜色从主题配置读取。原型里的数据都是虚构的。

- 首页是工作台；岗位库卡片进入岗位详情，字段可以点击修改。
- 侧栏的对话可以切换，覆盖六种状态：已生成简历的岗位对话、已匹配未生成、从岗位库打开未匹配、补充经历的普通对话、一般提问、新对话。
- 确认卡片、提问卡片、岗位标签菜单（切换、解除）、面板标签、依据追溯、简历编辑工具栏、岗位库筛选都可以点。
- 右下角「显示实现标注」显示每个区域用哪个组件、对应哪条设计、权限怎么分。
- 窗口宽度小于 992px 时，侧栏变抽屉，右侧面板改由顶部「查看结果」按钮打开为全屏层。

区域与组件、接口对照（接口见 [02 第 6 节](./02-技术架构与数据模型.md#6-接口v1)）：

| 区域 | 主要组件 | 主要接口 |
| --- | --- | --- |
| 侧栏 | Layout.Sider、Ant Design X Conversations、Dropdown（头像菜单） | `GET /api/conversations` |
| 消息列表 | Ant Design X Bubble.List、ThoughtChain（工具步骤）、自定义确认卡片 | `GET /api/conversations/{id}` |
| 输入框 | Ant Design X Sender + Attachments | `POST /api/conversations/{id}/messages`（SSE） |
| 确认卡片 | Card、Button、Select | `POST /api/conversations/{id}/actions/{action_id}` |
| 当前岗位菜单 | Dropdown | `PUT /api/conversations/{id}`（current_job_id） |
| 新对话欢迎页 | Ant Design X Welcome、Prompts | — |
| 简历标签 | iframe 内的简历模板与编辑脚本 | `GET/PUT /api/tailor-runs/{run_id}/resume`、导出 |
| 匹配报告 / 岗位标签 | Tag、Table、Typography | 由当前岗位读取 |
| 工作台 | Typography、Sender、Card、Statistic | 汇总接口（由事实库、岗位库、简历统计） |
| 岗位库 | Card、Tag（可选中的筛选标签）、Segmented | `GET /api/jobs?direction=&keyword=&city=&pay=&stage=` |

| 我的 | Statistic、Tabs、List、Select | `/api/facts*`、`/api/tailored-resumes`、`/api/memories*` |
| 账号设置 | Card、Modal | `DELETE /api/account`、`POST /api/account/restore` |

原型与本文档或 01～03 冲突时，以文档为准，并顺手修正原型。
