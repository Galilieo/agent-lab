# 参考：优秀开源项目怎样跟通用 AI 区分开

日期：2026-11-16。状态：参考资料，不属于冻结设计；文末「对 JobPilot 的启发」中哪些采用，由用户决定后再写进 00～07。

要回答的问题：通用 Agent（ChatGPT、Claude 等）已经有记忆、能读文件、能调用工具，**一个垂直领域的 Agent 项目凭什么让人用它，而不是直接用通用 Agent？**

资料来源：各项目的 README 与官方博客，以及部分第三方介绍（本次只读了 xerj、ASu-skills 的 README 原文，其余来自搜索结果摘要）。星数、版本等数字会变，以仓库页面为准；**项目自己报告的评测结果不等于独立验证**，例如 Mem0 的结果被 Zep 公开质疑过。

## 1. 八个项目怎么做

| 项目 | 做什么 | 跟通用 AI 的区别在哪里 |
| --- | --- | --- |
| [Aider](https://github.com/Aider-AI/aider)（Apache-2.0） | 终端里的 AI 结对编程 | **长在开发者已有的工作流里**：每次改动自动 git 提交，`/undo` 一键撤销；用 tree-sitter 生成「仓库地图」让模型看到整个代码库的结构；**自己维护公开的模型排行榜**，用固定题集比较各家模型的改代码能力 |
| [xerj](https://github.com/xerj-org/xerj)（Apache-2.0） | 给 AI 用的搜索引擎 | **不做 Agent，做 Agent 来查的引擎**：自带 MCP 服务，列出 26 个可接入的客户端并标明哪些测过；每条事实带版本和原文片段，程序校验片段与原文一致；数据不足返回 `UNKNOWN`、事实矛盾返回 `CONFLICT`；README 开头就是与通用模型（Opus）的实测对比，并写明局限 |
| [Mem0](https://github.com/mem0ai/mem0) | 给 Agent 用的记忆层 | **做基础设施，并用基准测试和通用方案比**：论文报告在 LOCOMO 上比 OpenAI 的记忆准确率相对高约 26%、延迟和 token 都更低。但 Zep 公开质疑其数字，说明自报的评测必须可复现，否则会被挑战 |
| [Open Canvas](https://github.com/langchain-ai/open-canvas)（MIT，2026 年 2 月已归档） | 对话加可编辑产物的写作工具 | **以产物为中心**：主角是右侧可编辑的文档，每个产物有版本可回看；有「反思」步骤把风格规则和用户信息存成跨会话记忆 |
| [ASu-skills](https://github.com/Hisn00w/ASu-skills)（MIT） | 中文求职技能插件 | **不跟通用 Agent 竞争，直接长在里面**：做成 Claude Code、Codex 等的插件，价值在流程、规则和简历模板 |
| [Reactive Resume](https://github.com/AmruthPillai/Reactive-Resume)（MIT） | 开源简历编辑器 | **数据归用户**：免费、可自托管、不追踪；完整导出、一键永久删除；隐私写在 README 最前面 |
| [Khoj](https://github.com/khoj-ai/khoj)（AGPL-3.0） | 个人的 AI 第二大脑 | **出现在用户已经在用的地方**：浏览器、Obsidian、Emacs、手机、WhatsApp 都能用；可自托管，可接本地模型 |
| [Perplexica](https://github.com/ItzCrazyKns/Perplexica)、[Morphic](https://github.com/miurla/morphic) | 开源的带引用答案引擎 | 定位是「开源版 Perplexity」：Perplexica 主打本地模型与隐私；Morphic 主打按答案内容现场生成界面组件。只说「开源替代」的区分度有限，要有自己的角度 |

## 2. 提炼出的六种做法

1. **一个核心机制做深，并给它起名字。** Aider 的仓库地图、xerj 的 Query-1。别人记住的是这个机制，不是「又一个 AI 工具」。
2. **用公开、可复现的评测和通用方案正面比较。** Aider 的排行榜、xerj 与 Opus 的对比、Mem0 与 OpenAI 记忆的对比。要公开题集、评判标准和脚本，否则会像 Mem0 一样被质疑。
3. **进入用户已有的工作流，而不是让用户换一个聊天框。** Aider 用 git，ASu-skills 进 Claude Code，xerj 走 MCP，Khoj 进 Obsidian、WhatsApp。
4. **数据归用户。** 本地运行、可自托管、能完整导出、能彻底删除，并写在显眼的位置。
5. **以产物为中心，而不是以对话为中心。** Open Canvas 的可编辑文档、Morphic 的生成式界面。
6. **诚实写局限。** xerj 写明测试题来自自己的开发集、哪些问题还做不好、哪些客户端没测过。诚实反而增加可信度。

另外两个具体机制值得单独记下：

- **改动可撤销**（Aider 的自动提交与 `/undo`）：AI 做的每一步都能回退，用户才敢放手让它改。
- **不确定就不答**（xerj 的 `UNKNOWN` / `CONFLICT`）：宁可拒答，也不猜。

## 3. 对 JobPilot 的启发

| 做法 | JobPilot 可以怎么做 | 现状 | 建议阶段 |
| --- | --- | --- | --- |
| 核心机制起名字 | 把「每一句都能追溯到你确认过的事实、程序检查不编造」命名为**可追溯改写**（Traceable Rewrite），作为 README 标题下的第一句和界面上「依据」功能的名字 | 机制已有，没有名字 | V1 |
| 公开评测正面比较 | 把 E5 做成可公开的**简历改写编造率基准**：公开合成简历、JD、编造标注和评测脚本；比较「只靠提示词的通用模型」与 JobPilot。V2 可以扩展成多模型的编造率排行榜，类似 Aider 的排行榜 | E5 已设计，未公开 | V1 公开数据与脚本；V2 排行榜 |
| 进入已有工作流 | MCP 服务（读取与生成类工具，含带依据检查的改写），通用 Agent 可直接调用；导出的 HTML 简历可交给任何 AI 继续修改；浏览器插件一键收藏 JD（已在待办池） | MCP 在 V3 | MCP 提前到 V2 |
| 数据归用户 | 本地运行、本地 OCR、发给模型前遮蔽联系方式、一键导出全部数据、两阶段删除账号；README 单独一节写清楚 | 大部分已设计，导出全部数据未明确 | V1 |
| 以产物为中心 | 工作台首页、右侧面板为主角、依据追溯 | 原型已做 | V1 |
| 诚实写局限 | README「局限」一节：评测是合成数据、样本量多少、哪些编造检查不出来（03 第 1.4 节） | 03 已列局限 | V1 |
| 改动可撤销 | Agent 每次经确认的写入都记录在 `agent_action`，提供「撤销上一次改动」；事实库本来就有版本，简历也保留旧版本 | 有记录，没有撤销入口 | V1 P1 |
| 不确定就不答 | 依据不足回退原文（已有）；增加**原文校验**：来自简历的事实必须保存原文片段，程序校验片段确实存在于简历原文；增加**矛盾检测**：同一件事说法不一致时（例如两处 GPA 不同）标出来让用户确认 | 回退已有；其余未设计 | 原文校验 V1；矛盾检测 V2 |

合起来，JobPilot 的定位可以写成一句话：

> **可追溯改写**：每一句都能追溯到你确认过的经历，程序检查不编造，并用公开的编造率基准证明；既能单独使用，也能作为通用 Agent 可以调用的求职数据层。
