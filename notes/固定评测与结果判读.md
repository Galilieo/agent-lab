# 固定评测与结果判读

正式进度以[学习路线第14节](./agent-lab总体学习路线.md#14-当前下一步)为准。本页从已有题集、探针与报告带读评测口径，尚未新增汇总实现或发起真实模型请求。

## 为什么要固定问题与资料

pytest中的假模型响应主要检查应用机制：消息是否传对、工具是否执行、异常是否传播等。固定评测使用明确的问题、资料和预期行为，观察真实模型与完整链路在这些场景下的输出；二者可以配合，不互相替代。固定输入便于比较版本，但真实模型仍可能波动，单次差异不能直接归因于某个修改。

本项目已经有playground/fixtures/rag_acceptance.json：四份合成资料、六道题。资料和问题可复用，不重新造大型题库，不新增评测框架依赖。旧报告只证明当时记录的版本和配置，不自动作为当前版本的新运行结果。

| 题目 | 想观察的能力 |
| --- | --- |
| batch_tag | 从资料准确获取苍鹭5836，给出对应出处 |
| timeout | 回答43秒，避免混入真实项目配置 |
| recovery | 先回滚、再继续抛原异常，顺序正确 |
| cross_document | 两种事实分别对应service与recovery出处 |
| missing_phone | 资料没有联系电话，如实说明、不编造 |
| greeting | 简短打招呼，不做无必要检索或编造引用 |

同题在without_knowledge与with_knowledge两组中的预期并不相同。关闭知识库时，资料题说明无法获知可以通过；不能因为没有答出资料事实就统一判失败。两组对照观察知识库是否提供有效帮助，不把对照组强行套入有资料组的答案标准。

## 已有代码与报告如何连接

playground/rag_acceptance_probe.py读取fixture，经正式/chat执行，保存response、model_calls、tool_retrievals、HTTP状态、耗时和落库计数；automatic_signals再从输出计算辅助信号。原探针失败后停止后续云端调用，所以计划题数不一定等于实际尝试数。阅读历史报告/离线计算指标本身不请求模型，显式运行原探针才会访问配置的真实服务。

automatic_signals中的all/any：每个answer_term_groups分组内任一同义词出现即可，所有组都命中才True；casefold做不区分大小写比较。它不理解否定、因果和操作顺序。比如“先抛异常再回滚”也能同时包含“抛”和“回滚”，仍违背恢复题要求。

expected <= cited只检查预期来源ID是否出现在返回来源中，不判断具体句子是否得到原文支持。no_invalid_citation_ids只看应用是否报告未知ID；一个存在的来源也可能被错误地用来支持另一条结论。号码正则仅匹配有限格式，不能证明完全没有编造联系方式。None表示该信号未提供或不适用，不能自动当成通过。

历史报告rag_acceptance_recheck_2.json中，without_knowledge/batch_tag的关键词与预期来源信号都是False，但manual_review.outcome为pass；其复核理由是没有资料时明确说明未知，未猜造事实。字段名manual_review沿用旧结构，reviewer实际为Codex，method明确非独立人工评审，不能把字段名当成真人审核证据。

## 四个维度分开记录

| 维度 | 证据与解释 |
| --- | --- |
| 请求执行 | HTTP失败/异常属于请求执行失败；HTTP200不保证事实正确。SSE未来还应结合error与缺终态判断，不能仅靠200 |
| 回答质量 | 根据组别、题目rubric、原资料和实际回答判断事实、顺序及不足说明，允许不同措辞 |
| 引用 | 区分ID合法、期望出处出现和原文真正支持结论；前两项可部分自动检查，后一项仍需语义复核 |
| 延迟与调用成本 | 本题elapsed_seconds是进程内/chat调用开始至完整返回；model_calls.latency_ms是各次模型调用耗时，total_tokens是供应商报告用量，缺失不填0 |

真实请求延迟包含检索、工具、模型及应用处理，不直接等于单次模型耗时之和；它不是浏览器首字延迟，也不是部署网络性能。历史批次elapsed_seconds还包含建索引等准备工作，不能和逐题请求耗时混用。

后续汇总至少区分计划题数、实际尝试数、执行失败数、有质量复核数与未复核数。请求失败率以实际尝试为分母；质量通过情况应同时报告复核覆盖，不能把未运行/未复核当成通过。为便于比较，还需保留题集/资料版本、代码版本、模型、Prompt和检索配置；对历史报告不存在的字段标缺失，不倒填成当时已经记录。

## 我的理解

待结合本项目的without_knowledge反例解释：自动信号是辅助证据，最终判定必须服从当前场景的预期行为；关键词、HTTP成功和合法来源ID各自能证明什么，不能证明什么。
