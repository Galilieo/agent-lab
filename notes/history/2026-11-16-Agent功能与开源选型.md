## 1. 当前候选组合

采用现有 Python / FastAPI / LangGraph / SQLite / Chroma 路线，围绕专用任务补齐能力。研究流程重点参考 GPT Researcher；Harness、子 Agent 和上下文重点参考 Deep Agents 与 DeerFlow 当前主线；Memory 比较现有结构化实现、ReMe 和 Mem0 OSS。

不把多个完整框架叠成执行链路。LangGraph 仍为编排候选；Deep Agents 先用于设计与小范围兼容性对照，不直接替换旧聊天入口。研究产品使用新任务存储，现有实验作为参考与回归范围。

算法与实现的候选组合：

| 职责 | 优先候选 | 采用方式与成立条件 |
| --- | --- | --- |
| 任务规划 | 结构化 Plan → Execute → 有限 Replan；LangGraph 条件路由 | Pydantic 校验计划；程序限制轮数。先测单 Agent，再加入最多两个研究实例 |
| 网页正文 | HTTPX 获取 + Trafilatura 提取 | 网络地址 / 重定向检查由应用负责；提取库只处理已获取 HTML |
| 关键词召回 | BM25s | 使用现成 BM25；中英文混排另测分词，不直接照搬英语 stemming 示例 |
| 语义召回 | 现有 BGE-M3 / Ollama + Chroma | 保留纯向量基线；索引绑定资料快照、版本与稳定 chunk ID |
| 混合融合 | 标准 RRF，优先 LangChain Classic 的 EnsembleRetriever | 单独验证新增 langchain-classic 依赖与现有环境兼容；按 chunk ID 去重，不混加 BM25 与向量原始分数 |
| 重排 | Sentence Transformers CrossEncoder + BAAI/bge-reranker-v2-m3 | 多语言现成模型候选；先量本机内存、耗时与检索增益，再决定默认开启 |
| 项目硬约束记忆 | SQLite 结构化事实 + 来源 / 修订号 | 明确覆盖、更新、删除规则，不引入自行设计的“重要性分数” |
| 语义 / 经历记忆 | Mem0 OSS 为集成对照候选，ReMe 为文件化与检索对照 | 先在隔离存储验证。与结构化硬约束记忆分工，不把召回结果当当前事实 |
| 任务恢复 | LangGraph SQLite checkpointer + 应用 Operation 记录 | 跨进程验证；外部请求未知结果保留，不宣称 exactly-once |
| MCP | 现有官方 Python SDK | 沿用项目锁定版本验证，不能照抄主分支新接口 |
| 语义评分 | Ragas + 本项目事实 / 版本 rubric | 复用评分器，保留裁判输入、判定与缺失值；先做人工标注校准 |
| 行为评分 | Deep Agents eval 设计；AgentEvals 作为可选轨迹匹配库 | 不要求自由研究路径逐步完全一致；检查必要动作和禁止动作 |

上述“优先候选”是有依据的设计选择，尚不是兼容性或效果验收结论。RRF 参数、召回数量、分块长度、压缩阈值只在开发集调整；不预设准确率或提速数字。

## 2. 功能按实际使用场景展开

| 功能 | 正常情况 | 必须考虑的变化与失败 | 可查看的产物 |
| --- | --- | --- | --- |
| 需求 / 计划 | 确认候选、版本、硬要求和偏好，生成调查维度 | 信息缺失先澄清；计划重做有限；过期修订不能确认 | 版本化计划、调整记录 |
| 工具调用 | 搜索、读取、查证、保存 Finding | 错参可纠正；空结果 / 超时可有限重试；未知工具不能执行 | 每步工具、参数摘要、结果 / 错误分类 |
| 在线调查 | 用搜索发现官方来源，读取正文后形成证据 | 搜索摘要不能充当已读原文；动态网页 / 404 留下原因；缓存注明获取时间 | 原文快照、哈希、版本、获取时间 |
| RAG | 在项目资料与已取得快照中找相关片段 | 新旧文档冲突、同名技术、代码标识符、近似但无关片段、资料不足 | 检索候选、重排前后顺序、最终交付片段 |
| Memory | 下一次任务复用已确认的技术栈与部署限制 | 当前要求覆盖旧偏好；用户修正后旧值失效；不同项目隔离；删除后不复活 | 查看 / 修改 / 删除、来源与修订、注入记录 |
| 上下文 | 只常驻任务摘要、证据索引、必要记忆和最近交互 | 长文 / 多工具导致超限；裁剪保留调用配对；摘要不能丢否定、版本与硬要求 | 输入预算、裁剪 / 压缩记录、可重读原文 |
| Multi-Agent | 分候选独立调查，协调者汇总缺口 | 历史互不污染；重复读取合并；一支失败保留另一支；总预算共用 | 子任务状态、来源归属、单 / 多模式 |
| Runtime | 排队、执行、等待确认、交付合法产物 | 取消停止新调度；断开只停止观察；进程恢复不重置预算；重复 resume 不重复调度 | Run / Operation / Event、恢复记录 |
| MCP / Skills | 通过 MCP 查询项目资料；Skill 提供可复用调查步骤 | 协议正确不代表选工具正确；工具列表变化、超时、断连有处理 | 实际协议轨迹、版本、能力说明 |
| 报告 | 比较表、建议、未知项及原文证据 | 版本不匹配、引用越任务、摘录错位阻断；语义不足单独标注 | 结构化报告、原文查看、Markdown 导出 |
| 工作台 | 计划确认、进度、证据、任务列表、导出 | 刷新事件不丢不重；partial / failed 不显示为成功 | 可录制的完整操作流程 |
| 评测 | 批量运行并保存质量、轨迹、成本和延迟 | 全部失败与未复核样本保留；用量缺失不填 0；裁判分歧可查看 | 逐题记录、汇总、失败分析、版本对比 |

网页内容属于资料，不能改变执行权限、任务目标或预算。第一版延续只读公开资料范围，仍不加入代码自动安装 / 执行、PDF/OCR、多人公网服务或任意浏览器操作。以后扩展这些输入时，单独设计与验收。

## 3. Memory 的具体选择

不能用一个“memory”标签混合三件事：

| 类型 | 保存什么 | 使用与可信度 |
| --- | --- | --- |
| 工作状态 | 当前计划、已完成分支、缺口、最近动作 | 任务存储 / checkpoint；用于继续当前任务 |
| 跨任务项目事实 | 项目技术栈、部署限制、用户确认的长期偏好 | SQLite 结构化记录；由应用绑定 project / owner / 来源 / 修订 |
| 经历与可复用知识 | 历史调查摘要、曾尝试方案、经验候选 | 可以语义召回，但要显示历史日期、来源和适用条件；重新核对变化的技术事实 |

完整 V1 纳入跨任务项目事实的查看、使用、更新与删除，不再把所有长期记忆留到后续。项目概况和偏好可以提取候选，但用户当前明确条件优先；网页不能直接改写用户事实。正式存储由应用控制，不能让模型伪造 owner 和来源。

语义记忆不另造算法：安排 Mem0 OSS 的小范围集成对照，并用同一任务比较无记忆、结构化记忆、语义记忆。若收益不足或成本不合适，保留结构化方案并记录结果。ReMe 优先参考来源回溯、文件化记忆、BM25 / 向量混合检索及评测分类；不同时运行两个长期记忆引擎。

记忆写入失败不能伪称“已记住”；删除与在途写入需要修订 / 删除标记保护。索引只是派生资料时，可以重建；若采用 Mem0 作为某类记忆的事实存储，就通过它的 Adapter 管理该类记录，不额外维护第二份并列真相。跨存储不假定事务天然一致。

### 4.2 源码核查发现的适配风险

- Deep Agents 的 MemoryMiddleware 主要加载文件并注入上下文，不等于完整的记忆提取、冲突消解和删除机制。其文件内容信任规则也需要适配我们的事实来源。
- Deep Agents 的研究示例会发现 URL 后获取整页内容；不能直接照搬成无限工具输出，仍需我们的大小上限、快照与按位置读取。
- Mem0 当前已读写入路径及评测文档采用 ADD-only 提取；add 的 docstring 仍提到自动 add / update / delete，文字与路径需要区别。不能仅凭方法名承诺自动覆盖冲突；显式 update / delete 和实际检索必须分别测试。文档中的时间参数也有平台与 OSS 区别。
- Ragas Faithfulness 会拆原子断言后判断支持度；缺少可评断言可能返回 NaN，不能统计成通过。对技术版本、否定与适用条件，必须加入自己的校准样本。
- RRF 的默认融合参数是库的默认，不是本项目最优值；重复文本不同来源不能因正文相同而丢失出处，必须使用稳定 chunk ID。
- 仓库许可证元数据显示核心候选主要为 MIT 或 Apache-2.0；实际复制代码时保留对应版权与许可证，并检查模型权重、数据集和子目录许可，不能用仓库标签替代逐项核对。

## 5. 使用前必须补的本地评测

不以“有官方成绩”跳过下面任何适用项。先建开发题和隔离工程场景；涉及真实模型、下载大模型、搜索账户或付费批量运行的试验另行配置执行预算。本轮没有启动这些动作。

研究效果先沿用原方案 20 题、8 开发 / 12 保留的起始安排。Memory 另外建立有完整历史的会话任务，按项目 / 会话族划分开发与保留；不能把同一历史的改写题拆到两组。冻结资料用于可复现分析，在线抽验单独报告，二者不混成实时搜索成功率。

每次记录代码提交 / dirty 状态、依赖、模型与权重 revision、提示词、资料哈希、参数、实际尝试、原始结果、来源、工具轨迹、用量缺失与失败。报告同时显示计划题数、实际执行数、已复核数、未复核数；不能从成功输出中另挑分母。单次偶然成功不当稳定性结论。

## 6. 接入顺序与采用规则

1. **任务与评测先行**：沿原阶段 A 准备目标报告、来源快照和开发题；同时准备 Memory 更新 / 删除与失败恢复场景。
2. **建立可测基线**：先完成单 Agent + 既有语义召回 + 事件 / 预算记录；保留无记忆模式用于对照。
3. **验证现成算法**：在隔离环境试 BM25s、RRF、重排模型；依次比较，出现回退或本机成本不合适时不强行默认开启。
4. **补齐 Memory / Context**：实现跨任务结构化记忆，做 Mem0 OSS 对照；按固定长任务验证裁剪、按需读取及必要压缩。
5. **多 Agent 与产品化**：沿原阶段 C / D 接入并行、跨进程恢复、MCP 与工作台，复用同一评测记录契约。
6. **保留题与演示**：完成原阶段 E，对各功能记录收益、代价和残余失败；公开项目的分数不能写入本项目简历成绩。

采用一个库前至少满足：许可证范围清楚；与当前 Python 3.12 及锁定依赖兼容；能限制 / 记录它实际产生的模型和工具调用；能在隔离数据上跑通正常与失败场景；本项目的对照结果支持该选择。评测效果不足可以保留为实验结论，不为了展示关键词强行放进默认路径。

当前代码未增加新依赖、未迁移业务存储、未接入新模型或收费服务。本页是后续实施和评测的设计基线，不授权自动提交、推送或部署。
